# Legal research source verification

The user describes a verification layer checked against **30–40 curated legal sources**. That is the only confirmed detail about the source set. The repository does not identify the sources, jurisdictions, update cadence, retrieval method or measured verification performance. This document sets out what a recruiter-facing explanation should make inspectable without claiming those details are already present in the product.

## What verification should make clear

For every legal proposition in an illustrative output, a reviewer should be able to answer:

- What precise proposition is being checked?
- Which source supports it, and is that source authoritative for the jurisdiction and issue?
- What pinpoint text or provision supports the proposition?
- Which version was consulted, and when was it checked?
- Does the cited material support the statement as written, including its scope and exceptions?
- What remains uncertain or requires human interpretation?

A source count alone cannot answer these questions. The described 30–40-source set should not be presented as comprehensive coverage, a guarantee of current law or a measured accuracy result.

## Suggested evidence record

A portfolio demonstration can show an evidence record with these fields: proposition; jurisdiction; source title and publisher; stable public URL; provision or pinpoint; quoted supporting text; source version or publication date; retrieval/check date; short explanation of support; known limitation; reviewer disposition. These are **recommended documentation fields**, not confirmed LegalGuard interface fields.

A useful review result distinguishes **supported**, **partially supported**, **not supported**, **conflicting sources** and **unable to verify**. It should not conceal a gap by generating a confident paraphrase. How LegalGuard labels verification outcomes is **to be documented**.

## Source set governance to document

- Inventory of the 30–40 sources, their publishers, jurisdictions and subject coverage.
- Why each source is included and whether it is primary, official guidance or secondary commentary.
- How source currency is assessed, versions are captured and updates are detected.
- How superseded, amended, inaccessible or conflicting sources are handled.
- How a reviewer proposes, approves or removes a source.
- Whether a result can be reproduced later from the cited version.

These points describe evidence a reader would need in order to evaluate the claim. They are not assertions about current system behavior.

## Synthetic demonstration outline

Use a fictional proposition and a clearly labeled public legal source only if the demonstration actually verifies it. Show the source version and pinpoint passage beside the proposition, then mark whether the passage supports the claim. Include a second scenario where a source is unavailable or ambiguous and show the result as unresolved. Do not fabricate citations, quote a real matter, or use a source outside its jurisdictional scope.

No legal proposition is validated by this portfolio. To add a real legal example, identify the jurisdiction and question first, then verify it against current official sources and cite the fetched source directly.

## Details to confirm

- Names and public URLs of the curated sources, with jurisdiction and subject.
- What “checked against” means in practice and which output types it covers.
- How pinpoint citations, source versions and dates are shown.
- What happens when a source conflicts, is outdated or does not answer the question.
- Whether the verification step is automated, human-assisted or manual.
- Any public evaluation method and results, if measured and approved for disclosure.

No accuracy rate or source coverage beyond the user-provided count is claimed here.
